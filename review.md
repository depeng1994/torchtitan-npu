## 2. Upstream `pass_pipeline` contract verification

Pinned source checked: `pytorch/torchtitan@v0.3.0` (tag commit `086bf6c166ec85c1298eb5596fa9bf95f6a2d840`).

| Upstream location | Relevant code / contract | Verification result |
| --- | --- | --- |
| `torchtitan/experiments/graph_trainer/configs.py:108-110` | `pass_pipeline: str = "default"`; docstring explicitly says it “Controls which graph pass pipeline, post-init hooks, and pre-train-step hooks are activated.” | The field is explicitly defined upstream as a shared selector, not only a pass-list selector. |
| `torchtitan/experiments/graph_trainer/trainer.py:126-127` (`GraphTrainer.__init__`) | `POST_INIT_HOOKS.get(self.config.compile.pass_pipeline, lambda _: None)(self)` | Post-init hook dispatch uses the exact same `compile.pass_pipeline` string. |
| `torchtitan/experiments/graph_trainer/trainer.py:221-225` (`GraphTrainer._make_fx_forward_backward_step`) | `PASS_PIPELINE_REGISTRY.get(self.config.compile.pass_pipeline, construct_default_graph_passes)` | Graph-pass pipeline dispatch uses the same string. |
| `torchtitan/experiments/graph_trainer/trainer.py:274-280` (`GraphTrainer.train_step`) | `PRE_TRAIN_STEP_HOOKS.get(self.config.compile.pass_pipeline, lambda _: None)(self)` | Pre-train-step hook dispatch also uses the same string. |
| `torchtitan/experiments/graph_trainer/registry.py:41-51` | `PASS_PIPELINE_REGISTRY`, `POST_INIT_HOOKS`, and `PRE_TRAIN_STEP_HOOKS` are separate registries, each keyed by string, with corresponding registration decorators. | The three registries are distinct, but their lookup key is deliberately shared through `compile.pass_pipeline`. |

**Correction to the original R2 severity:** the original factual statement that `pass_pipeline` participates in all three dispatches is correct. It is **not** the case that hooks use another field. However, the previous review wording could be read as claiming that changing `default -> npu_sdc_checksum` already drops an active v0.3.0 default hook. The inspected code proves the shared lookup contract, but does not by itself prove a current default-hook behavior loss. Therefore R2 is downgraded from **P1 / Blocker** to **P2 / Major** and is now framed as a composition/upstream-upgrade-resilience issue rather than a demonstrated current runtime regression.

## 6. Recommended implementation shape

| Area | Recommended direction |
| --- | --- |
| Ownership | Keep `SDC` responsible for detector config/lifecycle only. Put GraphTrainer compiler integration under the GraphTrainer extension layer. |
| Upstream integration | Prefer an upstream pass insertion/composition hook. If unavailable in v0.3.0, keep the local adapter minimal and isolated, and consider contributing the missing hook upstream rather than expanding local registry semantics. |
| Pipeline composition | Because upstream intentionally reuses `pass_pipeline` as the key for pass/post-init/pre-step registries, any local pipeline alias should either delegate those semantics or clearly remain an intentionally non-composable specialized pipeline. This is P2 unless a current behavior loss is demonstrated. |
| Checksum pass | Keep the shared `_insert_checksum_nodes` implementation and ordered custom op. Preserve idempotence. |
| Testing | UT the insertion predicates and all supported op targets; contract-test against the real pinned upstream pass list; add an NPU integration test that runs the actual GraphTrainer joint-graph path with Inductor. |
| User surface | Keep the current single NPU training entry and existing `--sdc.*` / `--compile.*` CLI. Do not add an SDC-specific script/config entry. |
