## Part 1/5 — MoE auto-overlap scheduler

### Review baseline

The replacement scheduler still has to preserve the correctness contract of upstream `ep_overlap_schedule_pass`: scheduling must not change tensor semantics; two-chunk regions must be validated; true EP token-exchange markers and their waits must be structurally valid; token-count D2H optimization must only rewrite the validated CPU-copy pattern; and a schedule that cannot be materialized safely must fail rather than silently weaken correctness constraints.

This review also applies the repository's reduction rule: every new scheduler abstraction/state/heuristic is presumed unnecessary unless the behavior cannot be expressed by reusing upstream region metadata/validation or a smaller cost-policy layer.

### Findings

| ID | Severity | Location | Dimension | Problem | Impact | Recommended change |
|---|---|---|---|---|---|---|
| P1-R1 | **BLOCKER** | `npu_moe_auto_scheduler.py:L191-L229, L1252-L1254, L1331-L1332` | Parallel correctness / cross-rank consistency | All agreement uses `torch.distributed.all_gather_object(...)` on the default WORLD group. `run()` checks `if not self.regions: raise` **before** the first WORLD gather. Communication-order agreement is required only among ranks participating in the relevant communication process group, not across unrelated groups/stages. | This is a compile-time deadlock/unsupported-topology risk, not just overhead. | P1-R8 | **MEDIUM** | `L291-L301, L556-L621` | Numerical robustness / cost model | Any exception from the compute benchmark is caught and converted to **0.0 ms**. Distinguish “unsupported node” from benchmark/runtime failure. | P1-R9 | **MEDIUM** | `L929-L948` plus repeated scans in `_select_next_launch`, `_select_slack_filler`, and the main loop | Memory / compile-time host bound / reduction | For every region, the scheduler materializes a transitive `set[Node]` ancestor closure for **every graph node**, then creates transitive successor relationships for region nodes. | P1-R10 | **INFO / maintainability** | `L264-L288, L486-L512` interacting with `compute_benchmark.py` | GMM maintainer comment / cost-model ownership | The GitCode question “why does GMM need special handling?” is valid to ask, but the special materialization itself is justified: `aten._grouped_mm` consumes value-sensitive cumulative expert offsets and may have a symbolic routed-token dimension. Generic random tensor materialization can generate illegal offsets; the benchmark therefore needs a balanced legal `offs` vector and an assumed routed-token count. The issue is that the scheduler now knows `_GROUPED_MM_TARGET`, permutation target sets, and their materialization assumptions. | Keeping the GMM behavior is necessary, but target-specific benchmark policy in the scheduler increases coupling and duplicates knowledge owned by `ComputeBenchmarker`. | **Do not remove the GMM-specific benchmark semantics.** Instead move “can benchmark / required routing assumption / assumption construction” behind the benchmark layer, so the scheduler asks for a cost with region routing metadata and does not branch on private target strings. This addresses the maintainer comment while reducing scheduler code and upgrade surface. |

### Additional observations

| Area | Result |
|---|---|
| Dependency safety inside one local region | The projected-ancestor approach correctly notices dependencies that leave and re-enter the region, but its correctness is weakened by the later “drop conflicting ordering edge and continue” fallback (P1-R3). |
| Communication swap agreement | The code correctly avoids making a local-only branch before the swap vote and includes local eligibility in consensus; however the consensus scope is wrong (WORLD rather than the actual PG), which is the larger issue in P1-R1. |
| Count/D2H intent | Pairing four token-count copies into one final host sync matches the upstream optimization intent, but this replacement omits the upstream structural validation required before changing blocking semantics (P1-R2). |
| Greedy long-communication fill | Slack reservation exists, but candidate ranking does not implement the advertised “large op first” behavior (P1-R6). |
| Whole-graph calibration interaction | Reusing profile costs by stable node ID is directionally sound; the first standalone round's positional cross-rank alignment is the inconsistent weak link (P1-R5). |
| GMM benchmark | Special handling is necessary for legal offsets/dynamic routed rows; ownership of that policy should move out of the scheduler (P1-R10). |
| Upstream decoupling | This 1356-line scheduler reimplements region ownership, exchange/wait pairing, D2H rewrite, dependency planning and topological ordering that upstream already treats as its scheduler correctness layer. The preferred architecture is “upstream validation/region semantics + thin NPU cost policy”, not a second independent scheduler contract. |

### Part 1 conclusion

**Changes required before this scheduler is acceptable.** P1-R1/P1-R2/P1-R3 are correctness/topology blockers. P1-R4/P1-R5/P1-R6/P1-R7 materially affect the claimed auto-scheduling behavior and upstream-decoupling goal. The GMM special case itself is justified; its placement/API should be simplified rather than removed.


## Part 2/5 — standalone compute/collective benchmarks and Inductor NPU benchmark patch

### Review baseline

Scope: `torchtitan_npu/extensions/graph_trainer/collective_benchmark.py`, `torchtitan_npu/extensions/graph_trainer/compute_benchmark.py`, and `torchtitan_npu/patches/torch_npu/inductor_benchmarking.py`.

The benchmark layer is part of scheduling correctness even though its outputs are “only costs”: all ranks that share a process group must execute an identical benchmark protocol; synthetic inputs must satisfy the real operator's semantic constraints; costs mixed in one scheduling model must represent the same quantity; and any temporary torch/torch_npu patch must be both upstream-bound and isolated behind an existing extension point where one exists.

For upstream context, this repository pins `torch==2.14.0.dev20260719` and `torch_npu==2.14.0.dev20260808`. PyTorch added the device-specific `register_benchmarker(device_type, ...)` dispatch registry in commit `7d75d0014956e5a1ecaa2ca44717529302f6e943` on 2026-02-28, before the pinned torch nightly. Ascend/pytorch later merged its standard `torch.profiler` PrivateUse1/mspti device backend in commit `a0bfa4ccc0e6c423312a0ec6f46d7fa4e8c86f30` / GitCode !44554 on 2026-08-19, after the pinned torch_npu nightly. The local patch header also points to pending upstream PR `https://gitcode.com/Ascend/pytorch/pull/46615`.

### What is correct in the current implementation

| Area | Review result |
|---|---|
| A2A load-balanced construction | `_build_a2a_split_matrix()` creates a valid source×destination matrix; each source's rows sum exactly to its input rows, and each rank's output splits are the corresponding matrix column. |
| Combine construction | Swapping dispatch input/output splits for combine correctly models returning the dispatched payload to its source ranks. |
| Event benchmark pairing | The event fallback records start before launch, executes `wait_tensor`, records end, synchronizes the end event, and takes a median; for an isolated single communication queue this is a sound launch-to-visible-completion measurement. |
| GMM legality | Balanced expert counts and cumulative boundaries are valid even when tokens < experts or some experts receive zero tokens. This special case should remain. |
| Permutation legality | The modulo routing generator balances assignments to within one and keeps expert IDs unique within a token when `topk <= experts`. Unpermute's inverse-index generation through the native permute operator is preferable to fabricated indices. |
| CANN cross-rank aggregation | Once samples are correctly associated, taking the per-sample maximum across ranks and then the median is a reasonable estimate of collective time observed by the slowest participant. |
| Upstream patch tracking | The file has an explicit community PR link (46615), satisfying the minimum traceability requirement. The remaining issue is implementation shape and deletion lifecycle, not absence of an upstream reference. |

### Part 2 conclusion

**Changes required.** P2-R1 is a distributed-liveness blocker. P2-R2/P2-R3 mean the current communication cost pipeline can either compare different timing semantics or hang without a recoverable fallback. P2-R4/P2-R5 should be resolved by shrinking the torch_npu compatibility layer around existing upstream extension points and deleting it once the minimum torch_npu includes the merged PrivateUse1/mspti profiler capability. The GMM/permutation/A2A special input construction is broadly justified, but it should be centralized behind one benchmark workload API, with the dynamic-permute row semantic fixed.


## Part 3/5 — whole-graph calibration, pipeline composition, shared utilities, and graph_trainer module move

### Review baseline

Scope: `torchtitan_npu/extensions/graph_trainer/whole_graph_benchmark.py`, `auto_overlap.py`, `utils.py`, and `graph_trainer/__init__.py`.

Two upstream contracts are especially relevant here:

1. Pinned TorchTitan v0.3.0 deliberately orders `ep_overlap_schedule_pass` **before** `concretize_ep_chunk_symbolic_shapes_pass`; its own pass-order test asserts this ordering. The concretization pass says it runs after scheduling has consumed the chunk-symbol contract, then rewrites/removes chunk SymInts, chunk metadata hints, and dead scalar/assert plumbing.
2. Runtime-aware graph-pass support is being tracked upstream by pytorch/torchtitan#4763. The current branch has a compatibility patch for the pinned dependency, so this review treats runtime context as a temporary upstream-bound compatibility mechanism rather than a new permanent NPU-only GraphTrainer API.

| Area | Review result |

### Part 3 conclusion

**Changes required.** P3-R1 is a distributed-liveness blocker. The current whole-graph trace is also not cleanly bounded to graph execution (P3-R2/P3-R7), and WORLD-min alignment is the wrong topology/statistic for an EP scheduling cost model (P3-R3/P3-R4). The two-round loop terminates but does not establish a fixed point and returns an unprofiled final schedule (P3-R5). Finally, moving the replacement scheduler after concretization violates the pinned upstream pass-order contract rather than merely replacing `ep_overlap_schedule_pass` (P3-R6). The module-to-package move itself is acceptable.

## Part 5/5 — tests, documentation, and example scripts

### Test-review baseline

This part follows the repository's test-review separation:

- **UT** is judged on CPU-observable production semantics and requires an independent oracle; a mock proving that a helper called another helper is not evidence for NPU behavior.
- **ST** is a separate coverage dimension. Real NPU/HCCL/profiler/stream behavior cannot be claimed from CPU UTs, synthetic traces, or example shell scripts.
- Test framework/runner behavior is not counted as product coverage.

The count is less important than the concentration: the blockers/highs are not cosmetic. They cluster around distributed liveness, scheduler correctness, cost-model validity, upstream contract compatibility, and the absence of real-NPU validation.

### 2. 必须修复项

Before this PR is mergeable, at least the following classes of issues must be resolved:

1. **Distributed protocol and liveness**
   - Replace WORLD-wide scheduler/benchmark/calibration agreement with the actual participating process-group scope (P1-R1, P2-R1, P3-R3/P3-R4).
   - Add coordinated failure/timeout behavior so one rank cannot throw or hang while peers enter the next collective (P2-R3, P3-R1).
   - Add real-NPU ST that executes the full distributed path rather than relying on mocks/examples (P5-R1).

2. **Scheduler correctness contract**
   - Restore the upstream token-count D2H structural validation before changing synchronization semantics (P1-R2).
   - Separate mandatory correctness dependencies from optional performance-ordering edges; never drop a mandatory edge to make a regional order acyclic (P1-R3).
   - Scope communication modeling to real/annotated EP exchanges and model independent process groups correctly (P1-R4/P1-R7).

3. **Cost model correctness**
   - Remove positional rank alignment and WORLD-min alignment; use stable semantic identity and the correct participant group/statistic (P1-R5, P3-R3).
   - Make CANN and event fallback measure the same quantity or store them as different metrics (P2-R2).
   - Fix dynamic permute source-token vs routed-token assumptions and host-bound/D2H cost handling (P2-R6/P2-R8).
   - Stop converting benchmark failures/invalid values into zero-cost compute (P1-R8/P2-R7).
   - Replace fixed “two rounds then return a third unprofiled schedule” with fixed-point/cycle-aware termination (P3-R5).

4. **Upstream GraphTrainer/Inductor contracts**
   - Replace the native scheduler at the native scheduler position; do not move scheduling after chunk-symbol concretization unless that new contract is upstreamed (P3-R6).
   - Use PyTorch's existing device benchmark registration seam instead of permanently monkey-patching `TorchProfilerBenchmarker.benchmark_gpu`; keep the torch_npu workaround explicitly temporary/upstream-bound (P2-R4/P2-R5).
   - Converge runtime context to upstream #4763's construction-time typed context/partial binding; the current `ContextVar + _requires_runtime_context` contract must not become a second GraphTrainer API (P4-R3/P4-R4/P4-R5).

5. **Tests and documentation**
   - Rewrite UTs that currently freeze known-wrong behavior (P5-R2/P5-R3).
   - Add missing distributed safety unit oracles and real NPU ST (P5-R4/P5-R6/P5-R1).
   - Refresh the feature guide after implementation fixes so documented safety/performance guarantees are enforced by code (P5-R9).

### 3. 建议拆分 / 删除项

To reduce PR scope and isolate ownership:

- **Remove `ep_forward_accumulation.py` and its test from PR 821.** The maintainer's inline direction is correct; #4708 is closed/unmerged and does not carry this EP-chunk patch. Wait for the Linan/upstream-approved ChunkLoss/functionalization solution and land it independently (P4-R1/P4-R2/P5-R8).
- **Treat the GraphTrainer runtime-context bridge as a separate upstream/backport concern** if the dependency cannot be bumped to #4763. The auto-overlap implementation should consume that seam, not own a permanent private protocol (P4-R3/P4-R4).
- **Keep the torch_npu Inductor benchmark compatibility patch independently upstream-tracked** by its Ascend/pytorch PR and delete it once the minimum torch_npu contains the required profiler capability (P2-R4/P2-R5).
- **Delete the bespoke DeepSeek-V4 `..._auto_overlap` config factory** and select the feature through existing CLI/config fields (P4-R6/P4-R7).
- **Delete `a5_graphtrainer.sh`** and reduce the A3/A5 auto-overlap wrappers to the minimum hardware-specific examples; do not create one shell/config combination per model/hardware/feature tuple (P5-R10).
- The pure `test_rope_recompute_integration.py` directory move is harmless but can be split/reverted as housekeeping if a minimal feature diff is desired (P5-R12).
- Remove the unrelated top-level empty `torchtitan_npu.experiments` import (P4-R10) and replace the new debug env surface with existing CLI-visible debug configuration (P3-R11/P5-R11).

### 4. Maintainer 判断

**当前不建议合入；应 Request Changes。**

The core idea—measured-cost EP overlap scheduling with whole-graph feedback—is reasonable, and several local input builders/tests are well-motivated. However, the current implementation creates a second scheduler correctness contract around upstream GraphTrainer while simultaneously introducing WORLD-scoped distributed coordination, private monkey patches, inconsistent timing/alignment semantics, and no real-NPU ST. Those are architectural and correctness risks, not follow-up polish.

The preferred direction is to substantially shrink the PR: retain upstream EP chunk/validation contracts, add a thin NPU cost-policy/scheduling extension at the upstream scheduler seam, use process-group-scoped distributed protocols, converge runtime context and benchmark registration to upstream hooks, and keep only the tests/docs/examples that prove those reduced semantics.
