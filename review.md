## 1. Overall assessment

| Dimension | Result | Notes |
| --- | --- | --- |
| Training entry / CLI | ✅ | No new shell entry or parallel config system is introduced. The change continues to use the existing NPU entry and `sdc` / `compile` CLI schema. |
| Patch-directory policy | ✅ | No code is added under TorchTitan/PyTorch patch directories. NPU-specific logic stays in the main repository. |
| Checksum implementation reuse | ✅ | GraphTrainer and normal Trainer share `_insert_checksum_nodes`; duplicate instrumentation is explicitly avoided. This is preferable to maintaining a second checksum implementation. |
| GraphTrainer architecture / upstream decoupling | ❌ | GraphTrainer experimental internals and global pipeline registration are placed in the generic SDC component, and the implementation takes over the upstream `pass_pipeline` dispatch key. This increases coupling to an experimental upstream subsystem and weakens extension composition. |
| UT quality | ⚠️ | Core positive/negative branches are covered, including idempotent insertion and invalid config. However the tests mock away the most upgrade-sensitive upstream pipeline contract and only positively exercise one of three declared matmul targets. |
| ST / smoke coverage | ❌ | The added NPU smoke test executes a hand-built single-`mm` FX graph with `aot_eager`; it does not execute the feature path claimed by this PR: `GraphTrainerEx -> joint fwd/bwd trace -> npu_sdc_checksum pipeline -> regional/full Inductor -> SDC lifecycle`. |
| Documentation | ✅ / ⚠️ | The guide is generally consistent with the code and explicitly states the smoke-test limitation. A class-level SDC docstring remains stale, and the documented custom-pipeline restriction is itself an architectural limitation that should be removed rather than normalized. |

Prefer an upstream-supported pass/hook extension point that composes with the active pipeline. If v0.3.0 lacks the needed “insert before terminal Inductor” hook, isolate a minimal GraphTrainer adapter and preserve/delegate the currently selected pipeline **and its post-init/pre-step hooks**; do not require `pass_pipeline == "default"`. Longer term, upstream the missing insertion hook rather than building more local registry semantics. Add a contract test proving existing pipeline hooks still run when SDC checksum is enabled. |

## 5. Recommended implementation shape

| Area | Recommended direction |
| --- | --- |
| Ownership | Keep `SDC` responsible for detector config/lifecycle only. Put GraphTrainer compiler integration under the GraphTrainer extension layer. |
| Upstream integration | Prefer an upstream pass insertion/composition hook. If unavailable in v0.3.0, keep the local adapter minimal and isolated, and consider contributing the missing hook upstream rather than expanding local registry semantics. |
| Pipeline composition | Wrap/delegate the selected upstream pipeline without losing its associated post-init/pre-train-step hooks. Do not force users to abandon another valid pipeline merely to enable SDC. |
| Checksum pass | Keep the shared `_insert_checksum_nodes` implementation and ordered custom op. Preserve idempotence. |
| Testing | UT the insertion predicates and all supported op targets; contract-test against the real pinned upstream pass list; add an NPU integration test that runs the actual GraphTrainer joint-graph path with Inductor. |
| User surface | Keep the current single NPU training entry and existing `--sdc.*` / `--compile.*` CLI. Do not add an SDC-specific script/config entry. |
